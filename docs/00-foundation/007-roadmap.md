# 🗺️ Project Roadmap

## Sindhi AI Keyboard

> **From a dependable keyboard for Sindhi users to a complete Sindhi AI technology ecosystem.**

---

# 1. 🌟 Roadmap Purpose

This roadmap defines the strategic path for Sindhi AI Keyboard from its foundational engineering stage toward a broader Sindhi AI ecosystem.

The roadmap exists to prevent uncontrolled feature growth while preserving the project's larger vision.

The project will not attempt to build everything simultaneously.

Instead:

> **Build the foundation correctly → ship a reliable keyboard → add intelligence → expand through Skill Packs → build the Sindhi SDK → grow into a broader Sindhi AI Platform.**

---

# 2. 🧭 Product Direction

The long-term direction is:

```text
Reliable Keyboard
        ↓
Language Intelligence
        ↓
AI-Powered Keyboard
        ↓
Domain Skill Packs
        ↓
Advanced AI Services
        ↓
Sindhi SDK
        ↓
Developer Ecosystem
        ↓
Sindhi AI Platform
````

The keyboard remains the primary product foundation.

---

# 3. 🧱 Roadmap Principles

Every milestone should follow these principles:

* ⌨️ Typing comes first.
* ⚡ Performance comes before visual complexity.
* 📡 Offline-first is mandatory for essential functionality.
* 📦 Packs prevent unnecessary resource consumption.
* 🚫 No intrusive advertisements.
* 🚫 No disruptive typing pop-ups.
* 🔐 Privacy is designed from the beginning.
* 🛡️ Security is continuous.
* 🧪 Testing accompanies development.
* 📚 Language assets remain properly documented.
* 🧩 Architecture remains modular.
* 🌍 International users must remain part of the vision.
* 🌱 Expansion must be sustainable.

# 7. 🟠 M2 — Keyboard Core

## Objective

Build the keyboard itself.

The keyboard must be useful before advanced AI is added.

### Core languages

* 🇸🇦 Sindhi
* 🇵🇰 Urdu
* 🇬🇧 English

The project should support the appropriate scripts and language-specific behavior rather than treating all three languages as simple layout variations.

### Layout philosophy

The existing Windows-style Sindhi keyboard layout is the reference point for the mobile experience.

The goal is to preserve:

* Familiar letters
* Familiar character placement
* Digits
* Numbers
* Punctuation
* Symbols
* Shortcuts
* Word/sentence shortcuts
* Existing typing muscle memory

Mobile-specific controls replace desktop keys such as:

* Shift
* Ctrl
* Caps Lock

where appropriate.

### Core requirements

* Fast input
* Stable rendering
* Accurate key handling
* Language switching
* Prediction
* Autocorrection
* Punctuation
* Numbers
* Symbols
* Themes
* Accessibility
* Keyboard settings

### Completion condition

A user can comfortably type daily messages without requiring advanced AI.

# 31. 🧭 Decision Rule for New Features

Before adding a major feature, evaluate:

1. Does it solve a real user problem?
2. Does it benefit Sindhi users?
3. Does it belong in the keyboard?
4. Can it operate without disrupting typing?
5. Can it work offline or degrade gracefully?
6. Does it require a new Skill Pack?
7. Does it introduce significant privacy risk?
8. Does it introduce significant operating cost?
9. Can the architecture support it cleanly?
10. Does it belong in the current milestone?

If the feature is valuable but not appropriate for the current stage, it should be recorded for a future milestone rather than forcing it into the current release.
